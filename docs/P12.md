# P12

Today and Runs replace the P11 placeholders. Run detail uses the existing member session and row security. The app keeps the P11 frame, six personas, language selection and phone navigation.

## Sixty second demo

1. Open Demo and choose Imran. Open the workspace. Today shows Needs action for me with approvals, blocked runs, assigned recovery and missing inputs older than two days. The bordered metric strip puts a number before one word.
2. Open Runs. Choose Client and First to last, then Apply. The address preserves the sort and direction. Open Harbor Coffee Roasters from the laptop table or phone divider list.
3. Review the timeline, findings and evidence beside the plan and exact approval. Each effect shows its destination, every record, every field before and after and all amounts. Emails show the recipient, subject and complete body. Reversibility and expiry remain visible.
4. Inspect the separate stale approval. Its sentence starts Out of date and ends Review again. Approve, Change and Reject are disabled. A direct call to execute is refused as well.
5. Approve the pending provision. Choose Execute approved work. The screen uses P7 to check the exact approval and current inputs, then schedules the existing P8 worker. Wait for Ready.
6. Open ClickUp. Read all eight tasks with owner, due date and status, the Live from ClickUp label and the time read. Choose Replay in Demo controls. Its result is the existing API message word for word. Open Inputs, Findings, Emails and History.

The browser test runs this path at widths 390 and 1440 in both languages. The test keeps its original sixty second limit. It requires no console errors and document and body widths equal to the viewport.

## Screen behavior

Today reads visible runs and actual metric rows. Approvals match the current roles and exclude a human requester. Blocked runs and old missing inputs belong to the current delivery lead. Recovery belongs to the current member. Empty categories say Nothing waiting here.

Runs shows Client, Deal, Status, Won, Ready and Owner. Every column can be sorted in either direction. Unknown sort values use Won and unknown directions use Last to first. Sorting uses a stable id fallback. Dates use Western digits. Missing dates and owners are explicit.

Run detail has Plan, Inputs, Findings, ClickUp, Emails and History tabs with the active tab in the address. The phone stacks the two columns. CSS uses logical edges. Stored quotes and exact outgoing record values remain verbatim. New labels have English and hand written Arabic messages. Soldline and Agent retain their names.

The approval countdown updates every second in the local browser timezone. Buttons are disabled for stale, expired or closed approvals and while requests are pending. Every decision reloads the stored state. The screen also refreshes every five seconds. It never executes work as a side effect of clicking Approve. Irreversible messages require the existing separate confirmation before Execute becomes available. Reject requires a nonempty reason in the browser. Change asks for a reason and uses the existing reject decision to return the current proposal for revision. Preparing the revised exact proposal remains the existing approval creation operation.

The screen execution route calls the existing approval HTTP boundary with its permission guard and only schedules the existing worker after success. The original execute route and all approval algorithms remain unchanged. The task reader checks stored membership and visible run ownership, uses the existing ClickUp client with the existing worker connection adapter and reads every task page. It returns an error when the current read fails. No saved task snapshot is substituted as a live result.
