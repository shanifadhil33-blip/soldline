## Created files

[Parser](../src/server/scope/parser.ts) extracts PDF text through unpdf and preserves page numbers. It parses English and Arabic scope headings, numbered items and bullets, quantities and cadences.

[Rules](../src/server/scope/rules.ts) contains the six pure comparison rules and matching by SKU, normalised title and approved mapping synonyms.

[Template](../src/server/scope/template.ts) declares the six required onboarding inputs. All are warnings by default. Blocking is a template property, separate from member writable onboarding records.

[Engine](../src/server/scope/engine.ts) assembles items, findings, evidence, suggested matches and the proposal.

[Storage](../src/server/scope/store.ts) exposes only saveDocument and analyseRun. The owner driver stays private. PDF ingestion stores page text and the SHA256 digest of the original bytes. Completed analysis creates a draft scope version, items, findings and the proposal atomically. Each created record and the plan update has one system audit row. Retrying a completed run creates no duplicate records. A document without extractable items stores a blocked message and remains eligible for another attempt.

[Workload reader](../src/server/scope/workload.ts) reads ClickUp list tasks through MSW in tests. It paginates, excludes closed tasks, rejects partial or repeated results, shares the existing token bucket by token fingerprint, and marks a rejected credential as needing reconnect. Requests have a time budget and distinct audit request ids. Owner selection uses only active members linked to ClickUp. Missing mappings or owners cannot permit provisioning.

[Proposal](../src/server/plan/proposal.ts) selects the eligible member with the lowest open task count, accounts for tasks already assigned in this proposal, computes calendar offsets in the workspace timezone and canonicalises JSON.

[AI chain](../src/server/ai/chain.ts) uses the ordered AI_PROVIDERS names. Each attempt has its own eight second timeout. The chain retries once. Output is Zod validated. Extraction runs only when the deterministic parser supplies no items. Matching suggestions are separately validated against existing item and line references, carry the visible label “Suggested match”, and require a person. They never clear a finding.

[Migration](../drizzle/sql/0006_scope_plan.sql) adds stored page text, line item cadence, mapping synonyms, mapping calendar offsets, mapping ClickUp list references and an explicit contract start date. Earlier migrations and permissions remain unchanged.

[Harbor fixture inputs](../tests/fixtures/harbor.ts), [scope tests](../tests/scope-plan.test.ts) and [storage tests](../tests/scope-store.test.ts) exercise the actual PDF, all six rules, AI failures, injection handling, timezone dates, system writes and audits.

## No invented quote proof

Tests present an invented quote, a real quote assigned to the wrong page, an empty quote, and an invented title paired with a real quote. Every invalid item is dropped. The provider chain test mixes a real item with an invented quote and retains only the real item. Validation also requires the title to occur in the quote and the quantity and cadence to agree with that title. This is deliberately stricter than checking quote presence alone.

An instruction inserted between real PDF items produces unusual_instruction with its quote. The original eight items, proposal hash and normal findings remain identical. No client instruction becomes a provider instruction or an accepted match.

## Verification and limits

Both pnpm test and the final pnpm gate pass 361 tests across 22 files. P6 adds 28 tests across two files. The gate completed lint, types, tests and the production build with exit code 0. It ran with output redirected to /tmp/gate.out and the exit code printed separately. Verification uses Node v22.23.3, Vitest, MSW and local PGlite. The requested unit tests skill was absent from the supplied catalog and the repo, so the existing test setup was used directly. No test assertion was weakened.

Provider adapters use explicitly configured compatible JSON chat endpoints. For a provider named sample, the server reads AI_SAMPLE_URL, AI_SAMPLE_KEY and AI_SAMPLE_MODEL. No remote endpoint is guessed. No environment file was opened or edited and no live provider call was made. Provider compatibility beyond the MSW contract remains unverified.

Analysis consumes the workspace scoped HubSpot line item mirror and supplied onboarding records. Email evidence belongs to the team inbox contract. It does not query Gmail. The signed PDF enters through the named ingestion operation. Automatic signed file retrieval remains parked because the existing HubSpot file URL path is unverified. The existing sandbox seed still contains its earlier placeholder scope and onboarding states and was left outside this phase. A full run detail screen and acceptance belong to later UI and approval work.

The contract start date and mapping ClickUp list ids must be supplied explicitly. Analysis refuses missing dates and incomplete mapping workload configuration rather than guessing. Scope versions stay draft for P7 review. Production database concurrency, live provider contracts, deployment and elapsed demo UI timing remain unverified.

No Neon connection, sign in, global installation, commit or push was performed. Permissions, job queue mechanics and earlier migrations were not changed.
