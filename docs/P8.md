## Self audit

The worst silent failure is a duplicate task after a timeout. In executor/worker.ts, apply calls taskMatches before parsing the task input, recording in flight or calling createTask. taskMatches reads pages from the exact target list and compares complete description lines with the exact run and item reference. Multiple matches stop execution. A match records succeeded and its external id, then returns without creating anything. This same path runs for initial creates and every retry. A lease reclaimed after a crash also enters this path for an in flight effect.

Every task create attempt has a completed marker reconciliation first checks the actual fixture call sequence and the persisted audit sequence for every executable task effect. Unknown task is adopted by its exact marker before any retry create simulates a successful remote creation followed by a network failure. The retry still ends with eight tasks. Marker reconciliation reads every page and refuses duplicate matches proves later pages cannot be silently ignored.

Mail stores its Message ID and draft observation before sending. Unknown and reclaimed in flight mail effects can only search sent messages and adopt an exact Message ID match. No match leaves the effect unknown and creates recovery work. Neither Retry now nor Reconcile can send that uncertain message again.

## Queue and database choices

P7 envelopes retain their existing approval keys and exact request hashes. Each executable record becomes a child external effect with the decided SHA256 key. This preserves the approvals core while storing each provider result independently. The first claimed P5 execution job owns the complete ordered approval sequence. Sibling envelope jobs become done with individual audit entries. One job therefore owns the existing five attempt budget instead of multiplying that budget by the number of envelopes.

The new migration adds parent effect references, stored result observations, cancelled job status and a unique running executor per run. Named private owner operations perform execution and recovery writes, following the existing jobs pattern. No new app role INSERT or UPDATE grant is needed. App requests still cannot directly mutate effects, approvals, jobs or audit rows. Both member and system audit writes use the existing append functions.

Recovery appears on the first execution failure so a person can intervene promptly. P5 still owns automatic backoff, leases, bounded attempts and dead handling. Dead execution jobs and expired fifth leases retain the four P8 recovery options. Resolving with a note stops further queued attempts and leaves unsuccessful effects unsuccessful. Pausing stops pending work and permits an already started provider operation to finish recording its outcome.

Reconcile only searches or adopts uncertain work. If more work needs a write, the item returns to recovery for Retry now. Folder and list reconciliation excludes ids observed before the uncertain create and refuses ambiguous matches. Container undo requires a stored and equal modification value and no remaining active children. Missing modification values cause refusal. Undo archives and never deletes provider objects.
