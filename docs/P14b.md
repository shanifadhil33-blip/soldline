The agent API accepts a question, optional threadId, and either a draft request or a structured card with its exact approval payload and input references. Draft requests name an action and runId. Plan correction drafts reuse a visible prepared plan. Reminder drafts require a supplied recipient and use missing inputs for wording. Scope drafts require supplied items and a reason. Recovery drafts bind the permitted item to a normal approval. Record text cannot select a card or execute a tool. Yes creates an ordinary pending approval atomically and is idempotent. Change persists a revised draft with its review note included in the exact approval payload. It does not interpret a free text note as authority to change delivery records. The normal human decision, confirmation and execution routes remain responsible for all effects. Client reminder effects use the existing default sample inbox path. An approved recovery retry effect delegates to the existing recovery store only after normal human approval and execution. It rechecks current membership, ownership, options and job state, then commits requeue and effect success atomically. It keeps recovery pending and does not mark the underlying delivery complete.

Agent wording calls use the existing chain, a provider allowlist, free OpenRouter model identifiers and the allowed Z.AI Flash model identifiers. Unavailable or disallowed configurations use deterministic data answers. Every outbound attempt consumes a daily quota. Demo members share the sandbox quota as well. No provider credential or environment file was read during this work.

Organisation suggestions no longer need two source runs. Supplied sources must be visible workspace records. Any member can suggest; client reviewers cannot list organisation memory. Small preference notes activate immediately. Explicit big lessons, other lesson kinds and text about checking or approvals wait for an Agency director. Directors and staff authors can edit or delete their organisation notes. Consequential edits return to review. Background run checking consumes only active big lessons that passed review; small notes are limited to conversational context. Forget permanently removes personal entries, conversation cards, messages and threads, preserving other people, organisation records, approvals and the audit chain.
