## Decisions and rule evidence

1. Recovery places the queue beside detail on laptops and before detail on phones. Only stored allowed options render. Each successful action selects the next item. The Recovery browser matrix exercises all four P8 actions and checks the next heading after each decision. The recovery collection unit test checks ownership and exact allowed options.

2. Resolve with note requires text and focuses the highlighted field when empty. The Recovery browser matrix proves both the refusal and a successful recorded note. A temporary internal route failure proves the branded error and that Try again repeats the action.

3. Undo appears for eight seconds only when the existing run has supported completed reversible effects and the member may request reversal. It occupies normal page flow above the queue and detail. The two reversible work browser cases execute real approved fixture work, check that the notice does not overlap detail, request the existing P8 reversal approval, assert the returned approval kind and check expiry with the browser clock. It never silently reverses an approval or sends an effect.

4. Audit is read only. Actor, action, outcome, run and date filters survive reload through the address. Dates filter UTC calendar days. Denied rows have an earthy tint. The Audit browser matrix checks every filter, reload, tint and stored Ravi name.

5. The full workspace chain is checked by the existing verifier before a successful audit response. English shows exactly Audit chain checked: unbroken or Audit chain broken at entry followed by the entry number. The broken chain route test supplies inconsistent hash observations at the SQL boundary and runs the real verifier. It returns the broken entry. The Audit browser error case proves that a failed read shows no unbroken claim and that Try again reads the checked result. Refused roles never receive the chain status.

6. Audit rechecks stored membership and roles. Admin reads all rows. Account manager and delivery lead read rows belonging to their own runs, including related approval, job, effect, finding, recovery, scope, input, inbound event and task targets. Contributor and client reviewer receive 403 from the API. The five role unit cases and the forged admin claim case prove this. The screen refuses known ineligible roles before fetching data, while direct API attempts still record a refusal. Event names, role titles and any recorded title come from the stored event fields rather than current member or record joins.

7. Connections show actual provider health, scopes and allowed actions without tokens. Known scope and action identifiers have plain language labels. Unrecognized capabilities use a neutral configured access label. The Connections matrix proves capabilities, pause, resume and reconnect. The contributor read unit case proves actual health is available without exposing credentials.

8. Only admins change connections. Every valid non admin change request returns 403 and appends a real denied audit event. The four role unit cases assert the actor, outcome, row count and unchanged provider state. The service uses stored roles even when a caller claims otherwise. Authorized changes delegate to P4. Pausing and resuming never clear a reconnect requirement, proved in unit and browser cases. Reconnect accepts a new credential and uses the existing encrypted token store. It performs no sign in.

9. Client collections use member row security and an additional explicit company predicate. A reviewer without a company receives no records. Input confirmation uses the existing input write grant and policies. Client approval first checks the visible deliverable under row security, then rechecks the stored member and company in the named owner mutation. Unit cases prove foreign input and deliverable writes are refused. Client browser cases prove Laith sees only Cedar, can confirm its input and can approve its deliverable in Client review.

10. Client approval is recorded separately from the provider observation. The new migration changes no existing grant or policy. Existing forced task row security and its WITH CHECK policy remain in place. No application table write grant is added. The approval pair has a consistency check and a workspace scoped member reference. The persistence test proves another observation retains the decision and a later review cycle asks for approval again. The monitor test proves an approved review does not generate a reminder.

11. Foreign company run and deliverable links use the same neutral missing page as absent records. The Client browser matrix compares the complete main text of each foreign and absent link. The route test compares the JSON responses and proves the foreign deliverable remains unchanged. Collection tests also cover a reviewer with no company and a reviewer holding another role. Foreign company links remain neutral even when that other role would grant wider staff access.

12. Backend check exists only in demo controls and its route refuses a real workspace. It builds a signed Ravi session in the same sandbox and invokes the existing exported plan approval POST with that Request. The response is the real route result. It then reads the audit collection and selects the newly created denial rather than inventing an audit row. The unit case repeats the check and proves the second row has a later id and that no approval was created. The browser matrix reads the same row independently and verifies the real 403 and full message. Missing and client sessions are refused.

13. White application surfaces and earthy accents use logical CSS. Audit rows stack on phones and the recovery columns stack in queue order. All five browser matrices run at 360, 390 and 1440 in both languages, measure body and document widths and check visible button and input heights. Links added by these screens have at least 44 pixels of height. The shared missing page has a main landmark. No overflow clipping hides a layout failure.

## Deviations and limits

There were no input routes, connection screen routes or client deliverable approval mutation to reuse. Narrow handlers were added around the current permissions, policies and services. The existing recovery routes and approval algorithms are reused unchanged.

P8 does not expose direct reversal of a queue decision. The Undo control requests its existing separate run reversal approval for completed supported effects. Notes and cancellation decisions are not reopened by an invented recovery operation.

Client approval is a durable Soldline review decision. It does not update remote ClickUp status. Provider synchronization remains outside this screen task. The new migration must be applied by the normal deployment process before serving the updated app against an existing database. Fixture databases apply it automatically.

The backend panel uses the exported route handler with a real signed Request inside its demo bridge. It does not make a separate loopback HTTP hop. The browser sees the request description, response status, full server message and stored audit identity. The exact route path is also in the returned request metadata.

Unknown provider capability identifiers receive generic plain language descriptions. No provider scope parser or client path constant changed. Production concurrency, provider compatibility, remote scheduling, deployment and the earlier live acceptance work remain unverified.

No existing test assertion was removed or weakened. Early browser runs found ambiguous control lookups and the missing main landmark. Those were corrected. One demo open interaction timed out during an earlier broader matrix. The complete rerun passed all 83 checks without increasing a timeout or enabling retries, and the final trust rerun passed all 32 checks.

All source changes and browser artifacts remain inside the repo. The requested gate output is the sole intended artifact outside it. No environment file was opened or edited. There was no sign in, live HubSpot, ClickUp, Gmail, AgentMail or AI request, global installation, commit or push. Earlier migrations, approval algorithms, executor reconciliation, scope parser and integration path constants are unchanged.
