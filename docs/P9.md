The parameter tests include one second under, exactly at, and one second over the relevant limits. Working time uses the workspace timezone and actual local day boundaries. Weekends do not count. Missing input age uses elapsed time. Deadline risk covers future due times through two days inclusive.

Missing input and review findings belong to an account manager. Deadline and ownership findings belong to a delivery lead. The run or deal owner is preferred when he has the right role. Another member with that role is next, followed by an admin. A workspace without an eligible owner retains an unassigned finding rather than inventing a member.

The P8 recovery table, finding identity and resolve with note option are reused. A new unique index enforces one recovery per finding. The scan is serialized per workspace. Dismissed and manually resolved findings are respected. Only findings closed because their condition cleared may reopen automatically. Email requests remain for a person to resolve.

Every company entry waits for admin review. This deliberately avoids guessing the impact of free text. Creation requires two distinct real run records and an explicit yes. Private staff performance lessons are refused until a private manager view exists. The Memory page supports personal entries, preferred names, editing, deletion, Undo, export and confirmed clearing. Its words and layout follow the member language. It shows company labels and record counts. Removed entries remain visible for Undo and are excluded from active context and export.

Personal context returns all active confirmed entries for that member and the active confirmed company entries allowed for his audience. It names each used entry in its reasons. Background email classification receives only active confirmed company memory from its own workspace and records the memory ids and reason with its finding. It never receives personal memory. The repo has no general conversation engine to wire beyond this context operation and the existing classification path.

## Undo refusal

The worker now takes a workspace scoped member lookup. A ClickUp editor takes precedence over an assignee. An assignee is used only when the API omits the editor. The member display name comes from his ClickUp user id. An unmatched editor uses the requested Someone sentence, even when an assignee would match.

The existing test Undo is a separate reversal approval and refuses a task changed by Ravi still passes with Ravi in the member fixture. Undo uses Someone when the task editor has no matching member covers the fallback. Executor changes are confined to this lookup and preserving its refusal in recovery.

## Scope self audit and limits

P9 has no scope version or scope item write operation. The mail test sends both casual words and an explicit request through the existing P5 storage path, runs repeated scans, and compares every scope version and scope item before and after. Both remain identical. Reminder drafting calls createApproval and creates no provider effect or mail request. Approval and executor behavior outside the allowed refusal remains unchanged.

The requested global statement that every scope version write requires an executed scope change approval is not true of the inherited repo. P6 creates draft scope versions in its existing analysis store before approval. P8 explicitly parks accepted scope mutations because the approved execution contract is unspecified. P9 does not invent that contract or alter P6. The proof delivered here is that P9 and email cannot change scope. A database owner can still write scope records, as existing PGlite fixtures do. Broader enforcement remains outside this phase and must be resolved before claiming the global invariant.

ClickUp review time starts at the first successful observation of Client review and resets when an observed status leaves it. The API has no confirmed status entry history contract here. A transition away and back between polls cannot be inferred. Reads cover P8 created task references. External tasks without a confirmed link to a scope item cannot satisfy a commitment automatically.

Reminder recipients and exact wording must be supplied by a person through the reminder route. The client company model has no confirmed reminder recipient. No recipient is guessed and the monitor does not silently draft mail to an invented address.

The unit tests skill was absent from the available skills and repo. Existing Vitest, MSW and PGlite were used. New writes run through fixed named owner operations. No new app role INSERT or UPDATE grants were needed. The new task table has enabled and forced row security, restrictive workspace and run policies, and SELECT only. The new migration also narrows company memory reads to admins. Earlier migrations and the permission matrix were unchanged. Audit writes use the existing append functions only.

Whole app language switching, a general conversation interface, notification screens and live subscriptions, monthly task interaction measurements and measured estimate error remain outside the current server phase. No missing measurements are presented as actual results.
