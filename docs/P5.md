## Signature self audit

In src/server/events/http.ts the HubSpot handler reads request.text, then calls verifyHubspot. Failure returns 401. JSON.parse appears only after that return branch. Portal lookup, event insertion and job creation are later. Signature failure tests send malformed JSON and prove JSON.parse is never called, no event is stored and no worker is registered.

The ClickUp handler reads request.text and tries HMAC verification against the stored encrypted webhook secrets. It does not inspect the body to select a secret. If there are no MAC matches it returns 401. Only then does it call JSON.parse and check that the parsed webhook id belongs to a matching secret. A valid secret for another webhook id is refused. Malformed JSON with an invalid signature returns 401 rather than a parse error. A source assertion checks that JSON parsing in both handlers occurs after the signature refusal branch.

HubSpot uses base64 HMAC SHA256 over method plus the provider specified full URI representation plus raw body plus timestamp. The timestamp must be within five minutes in either direction. Comparison is timing safe. ClickUp uses hex HMAC SHA256 over the raw body with a timing safe comparison. HubSpot performs only the URI escape decoding specified for its v3 signature format.

## Decisions and deviations

The requested unit tests skill is absent from the supplied catalog and the repo. The existing Vitest, MSW and PGlite setup was used directly.

The existing permission detector assumed all mutations had member authentication. It now also accepts the closed withSystemRoute factory from the exact server module, with only the four fixed handler names. It still rejects unchecked callbacks, unknown names, fake imports and forgotten member guards. Negative cases were added. The factory itself selects authenticated handlers and accepts no arbitrary callback.

Worker provider reads live in the jobs module so their HTTP abort deadline covers the entire worker budget without changing the P4 integration clients. They reuse the existing paths, schemas, encrypted credentials, persistent rate buckets and fixture contracts. Provider failures are redacted and retried by the job queue. The worker does not start another job after its time budget ends. A short database commit can still finish after the deadline, and a slow database itself has no cancellation guarantee.

The migration adds cursors and won stage settings to connections, delivery lead and mail routing to runs, run links to event receipts, lease tokens and one recovery item per job. Recovery run_id is nullable because scheduled connection jobs can fail before a run exists. Recovery for a run uses that run's delivery lead. Scheduled recovery uses the connection's configured lead. Existing tables retain their row security and direct app writes remain denied.

Replays retain the original receipt and source. They pass replay provenance to the same handler and record received_via replay in the audit details. This preserves the original transport provenance while recording every replay attempt. Raw HubSpot events retain unknown provider fields.

When a deal is missing locally, the worker imports its snapshot before making the run. A missing company name remains the plain placeholder Client. A missing company association gets a local pending reference. P6 owns enrichment and analysis. The accepted scope items hash is used when present. Otherwise the scope version identity, or a stable pending value, supplies the hash until P6 has parsed a scope.
